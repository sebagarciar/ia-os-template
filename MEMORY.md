# Memory: learned rules

Lessons taught by correction. Check these before every task. New rules go at the bottom.
Before adding a rule here, check where it belongs: `context/lesson-routing.md`.

These three are examples of the shape a rule takes. Replace them with your own as you work.

## How I communicate with you

- **A risk gets flagged once.** Once I have warned you about something and you have decided, it is
  closed. Do not bring it up again at every wrap-up.

- **Two-way doors swing freely, one-way doors stop.** A two-way door is a step I can undo (edit a
  file, try a layout, run a local test): go through it and show me after. A one-way door cannot be
  undone (delete data, send a message, publish, spend money): stop and ask first. If my answer
  would be a rubber stamp, do not ask. If running something can answer the question, run it.

## Getting things done

- **Before saying "I can't", look for another route with the tools you have.** Check the
  connected tools first (mail, drive, calendar, GitHub). The copy I want often sits somewhere you
  can reach. Say what you tried, then what you could not do.
